## Realtime exposure

Supabase Realtime has two mechanisms. **Postgres Changes** streams row changes for tables
added to the `supabase_realtime` publication. **Broadcast** carries named topics, authorized
by row policies on `realtime.messages` keyed on `realtime.topic()`. An empty publication
does not mean no realtime exposure — it means the exposure is on the Broadcast side.

## Appendix: declared intent

The author's `COMMENT` on each resource. This is a **claim about** the control, recorded
beside the measurement so the two can be compared. It is not evidence and no test result
depends on it.

- `private.career_drill_seeds` — The secret a drill attempt's scenarios are derived from. Never leaves the server; regenerated at grading time so a client cannot answer a different question from the one it was asked.
- `private.game_commands` — Accepted-command idempotency ledger. A duplicate clientActionId returns the first committed response unchanged. Server-only: no API role has any privilege on this table or on the schema that contains it.
- `private.game_state_private` — Authoritative BlackjackGameState including future shoe order and the dealer hole card. No API role has any privilege on this table or on the schema that contains it.
- `public.blocks` — Directed block. Readable only by the blocker: a blocked user is never told.
- `public.career_attempts` — One reward-bearing attempt at one career node. Every counter is written by the server from its own authoritative state; the client reports nothing. career_progress is the aggregate computed from these.
- `public.career_nodes` — Public catalogue of career objectives. Written by seed data and migrations only.
- `public.career_progress` — Per-user career progress. Readable by its owner; every write, including reward payment, is server-controlled.
- `public.cosmetics` — Public cosmetic catalogue. No price column and no randomised unlock type exists by design.
- `public.daily_challenges` — One challenge per date. seed_secret is server-only; seed_commitment is the published SHA-256 that makes the shoe verifiable after the fact.
- `public.daily_challenges_public` — Client-facing projection of daily_challenges with seed_secret absent. security_invoker, so the row policy still applies.
- `public.daily_entries` — One attempt per user per challenge. Readable only by its owner; leaderboards are published as server-produced, public-safe output.
- `public.friend_requests` — Readable only by the sender and the receiver.
- `public.friendships` — Undirected friend edge, stored once with user_id_a < user_id_b. Created only by server code.
- `public.game_events` — Append-only, sanitised event stream. Participants read public rows; a seat-scoped row is readable only by its recipient.
- `public.game_session_seats` — Seat occupancy and table stack. Membership source for every game-scoped RLS policy.
- `public.game_sessions` — One table/room. Public, sanitised metadata only; the authoritative engine state lives in private.game_state_private.
- `public.hand_players` — One settled player hand. net = credit - wager is a database constraint.
- `public.hand_records` — Completed-hand archive. Dealer cards may only be stored once completed_at is set, so the hole card cannot leak through history.
- `public.loadouts` — Equipped cosmetics. Client-writable, but every slot is validated against ownership and kind by trigger.
- `public.matchmaking_queue` — Players waiting for a public seat. Allocates seats only — chips move through apply_wallet_delta in the session function, never from here.
- `public.notifications` — Server-written user notifications. Clients may only mark them read.
- `public.player_actions` — Per-decision log with optional strategy grading. Readable only by the player who made the decision.
- `public.player_daily_xp` — Repeatable XP earned per UTC day, for the 300/day cap. Server-written only.
- `public.player_decision_periods` — Server-graded basic-strategy decisions per player per ISO week. Written only by record_decisions, which is reachable by no API role. Practice, private tables and tournaments are excluded before a row is ever written.
- `public.player_mode_stats` — Server-written statistics bucketed by mode and ruleset version. Private to the owning user.
- `public.player_stats` — Server-written lifetime statistics. Private to the owning user.
- `public.profiles` — Public-facing player identity. level and xp are server-owned and are not client-writable.
- `public.push_tokens` — Per-device push registration. A user manages only their own rows.
- `public.rate_limit_events` — One row per ALLOWED attempt. Refusals are not recorded — see the header of this migration. Pruned on every consume, so the table holds at most one window of history per player per action.
- `public.rate_limit_policies` — Every rate limit in the product, in one place. Read through rate_limit_for(); never duplicated as a literal inside a function. Server-owned: no client role holds any privilege on it, and RLS is enabled with no policy, so it is unreachable through PostgREST even if a grant were added by accident.
- `public.rooms` — Private tables. No wallet movement is possible from here — seats use a fixed session stack, which is the anti-collusion rule, not a shortcut.
- `public.rulesets` — Persisted BlackjackRules values. Public read-only catalogue; written only by migrations and server code.
- `public.tournament_entries` — Registrations and standings. Publicly readable; created only by the server so the entry fee and the entry commit together.
- `public.tournament_matches` — Bracket slots. A winner must be one of the two entries in the slot.
- `public.tournaments` — Public tournament catalogue. Server-written.
- `public.user_cosmetics` — Server-granted cosmetic ownership. Readable by its owner; no client write path.
- `public.wallet_ledger` — Append-only chip ledger. Every row carries a unique idempotency key; UPDATE is rejected for all roles.
- `public.wallets` — Global virtual-chip balance. Server-authoritative: readable by its owner, writable by no client role.
