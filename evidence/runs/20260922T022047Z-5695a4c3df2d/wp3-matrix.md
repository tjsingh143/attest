## 3. Execution versus assurance verdict

Every evidence record carries **two** independent fields, so that "the probe did what we
predicted" can never be read as "the control holds".

| Field | Values | Says |
|---|---|---|
| `observation` | as_predicted / not_as_predicted / harness_error | did execution match the prediction |
| `verdict` | effective / deficient / characterized / gap / not_measured | what that means for the control |

The two come apart in exactly the places that would otherwise produce a false green:

- **F7 owner bypass.** The probe returns every row, precisely as predicted, because row-level
  security is enabled and not forced. `observation: as_predicted`, `verdict:`
  **`characterized`** — a fact was recorded and no control was asserted either way. It is
  never `effective`, because the control was not applied at all.
- **F10 audit trail.** The probe confirms no trail exists, precisely as predicted.
  `observation: as_predicted`, `verdict:` **`gap`** — the control does not exist to be
  exercised.
- **Partial trails.** Two of the four structures that look like audit trails answer only part
  of who-did-what-when, so their existence check also records `gap` rather than `effective`.

A harness error remains a third, separate state: it never matches an expectation, renders as
`HARNESS ERROR`, and yields `verdict: not_measured` (DECISIONS D1.13).

Planned verdicts when execution matches: **256** effective, **23** characterized, **19** gap.
